## 会话复盘

### 发生了什么
- 路线 A 将 Potluck/模型统计的高频全量同步写改为有界 debounce 持久化，并补齐 worker/master/request-audit 的关停 drain。
- 集中回归暴露两个与 OOM 直接相关的隐藏放大点：`file-lock` 正常完成后残留 30 秒 timeout，以及 refresh wrapper 超时后底层 adapter operation 未纳入 shutdown drain。

### 高信号问题
- Windows 命令长度：展开 95 个 Jest 绝对路径时报 `The command line is too long.`；改用 `--testPathIgnorePatterns=api-integration.test.js` 后可稳定完成全量回归。
- 超时器生命周期：`Promise.race` 的 timeout 必须在成功、失败和超时三种路径统一清理，并区分“业务 wrapper 已超时”和“底层 operation 已真正结束”。
- 日期测试：涉及“距今天数”的 fixture 必须冻结系统时间，否则会随自然日期漂移失败。

### 下次默认做法
- Windows 全量 Jest 优先使用 test pattern/ignore pattern，不展开大量绝对路径。
- 新增 timeout wrapper 时同时增加 timer-count 测试；新增 shutdown drain 时测试 wrapper timeout 后底层任务仍 pending 的场景。
- 所有固定日期 fixture 使用 fake timers/setSystemTime。

### 建议沉淀更新
- 可在项目测试约定中补一条：全量回归使用 `npx.cmd jest --runInBand --testPathIgnorePatterns=api-integration.test.js`，环境集成测试单独运行并记录鉴权前提。

### 后续需要确认的决策点
- 历史统计修复需要用户确认数据源覆盖范围和闭日 cutover；本轮未修改生产数据。
